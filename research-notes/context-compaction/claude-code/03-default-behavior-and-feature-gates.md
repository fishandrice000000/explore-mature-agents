# Context compaction - Claude Code - 03 - Default behavior and feature gates

---

我注意到这个上下文压缩机制中存在许多"判断XX是否可用"的过程. 更令我感兴趣的是: 上下文压缩机制的默认行为是什么样的? 哪些功能是默认开启的?

---

## 结论先行

先要给“默认”拆成四层，否则答案会混在一起：

1. **用户配置默认值**：新配置里自动压缩是开启的；
2. **环境变量默认值**：默认没有任何禁用或覆盖变量；
3. **远端开关默认值**：代码里写死的 fallback，GrowthBook 没有下发时使用；
4. **构建期开关**：某一版发行包有没有把某段代码编译进去，源码快照只能看到分支，不能看到该发行包的实际取值。

如果指的是“外部发行版 + 默认配置 + 远端没有下发任何覆盖值”，那么默认行为可以概括为一句话：

> **自动压缩默认开启，但真正会改写历史的主路径只有整段摘要；工具结果聚合预算、时间微压缩、会话记忆压缩、历史剪裁、上下文折叠、缓存编辑式微压缩、响应式压缩都不在默认路径上。**

默认仍会发生的周边上下文管理是：

- 单条工具结果超过约 50K 字符时转存磁盘，只留预览和路径；
- 到达约 167K token 时触发整段摘要；
- 摘要默认尝试复用主对话的提示缓存；
- 压缩后重新注入最近文件、计划、技能、后台代理和工具/MCP 状态；
- 在支持的第一方模型上，默认请求保留历史思考块；空闲超过 1 小时后改为只保留最近一轮思考，而且这个状态会在本会话内锁存。

在默认 200K 模型、模型最大输出不低于 20K 的条件下，用户能看到的大致节奏是：

| 位置 | 默认行为 |
|---|---|
| 约 147K token | 界面开始显示“距离自动压缩还有 N%” |
| 约 167K token | 自动压缩触发，生成整段摘要并继续当前回合 |
| 约 177K token | 硬阻塞线；正常情况下自动压缩会先处理，只有自动压缩关闭或连续失败时才会在这里拦截 |

这些数字是代码默认值。生产环境的 GrowthBook 可以按用户、模型或实验组分发不同取值，因此“线上所有用户都如此”不能从本地源码证明。

## 场景

用户使用默认配置开了一个长会话：读文件、跑测试、看日志。上下文逐步增长。

在默认外部构建里，工具结果会先被单条阈值截住一部分；但不会再有“同一轮多个工具结果合计超预算”的清理，也不会有“空闲一小时自动清理旧工具结果”，更不会先尝试会话记忆。到了自动压缩阈值，系统直接进入整段摘要：fork 一个摘要代理，复用主对话缓存，生成交接摘要，再重建文件和工具状态。

这就是默认路径和完整机制图之间最大的差别：**完整机制图描述的是所有可能路径，默认路径只是其中一条主干。**

## 机制展开

### 1. 四个“默认”来源

**用户配置。** 新配置对象的自动压缩字段默认是 `true`。用户可以在设置里关掉自动压缩，也可以设置环境变量只关自动压缩、保留手动 `/compact`。

**环境变量。** 默认没有设置。它们主要用于禁用、压低窗口或测试阈值，不是常规用户的默认状态。

**远端开关。** 代码里的 `getFeatureValue_CACHED_MAY_BE_STALE(name, defaultValue)` 会在 GrowthBook 不可用、没有缓存值或没有该字段时返回代码默认值。生产环境一旦下发，代码默认值就可能被覆盖。

**构建期开关。** `feature('...')` 在打包时决定某段代码是否进入发行包。源码快照没有构建配置，因此只能根据注释判断哪些是内部构建专用；不能从 `feature()` 的调用本身推出外部发行版的取值。

### 2. 默认开启的功能

| 功能 | 代码默认 | 说明 |
|---|---|---|
| 自动压缩 | 开启 | 新配置的自动压缩字段为 `true`；受用户设置和环境变量影响 |
| 手动 `/compact` | 开启 | 只要没有设置全局禁用变量就可用；不会自动继续提问 |
| 摘要缓存共享 | 开启 | 摘要代理默认复用主对话的系统提示、工具和消息前缀；失败后退回普通流式摘要 |
| 整段摘要与压缩后重建 | 开启 | 自动压缩和手动压缩共用；包括文件、计划、技能、后台代理和工具/MCP 增量 |
| 单条工具结果转存 | 开启 | 多数工具超过约 50K 字符就转存磁盘；读取工具按自己的读取上限处理 |
| 硬阻塞线检查 | 开启 | 每次调用前都会评估；正常由自动压缩先处理，关闭或失败时成为兜底 |
| 压缩后清理 | 开启 | 清空已读文件缓存、系统提示分段缓存、记忆文件缓存等 |
| API 侧思考保留/清理 | 条件开启 | 第一方或 Foundry 的现代模型、启用思考时默认保留历史思考；空闲超过 1 小时后只保留最近一轮，并在本会话内锁存 |
| 压缩警告 UI | 开启 | 接近阈值时显示剩余百分比或“运行 /compact”提示 |

### 3. 默认关闭或默认不存在的功能

| 功能 | 默认状态 | 原因/边界 |
|---|---|---|
| 单条消息工具结果聚合预算 | 关闭 | 远端开关默认 `false`；关闭时仍保留单条结果转存 |
| 时间触发微压缩 | 关闭 | 远端配置默认 `enabled: false`；默认参数是 60 分钟、保留最近 5 条，可由远端覆盖 |
| 会话记忆提取 | 关闭 | 远端开关默认 `false`；只在自动压缩开启且主 REPL 线程时注册提取钩子 |
| 会话记忆压缩 | 关闭 | 需要 `tengu_session_memory` 与 `tengu_sm_compact` 同时为真 |
| 摘要流式重试 | 关闭 | 远端开关默认 `false`；缓存共享失败后的普通流式摘要默认只尝试一次 |
| 响应式独占模式 | 关闭 | 远端开关默认 `false`；开启后主动自动压缩会被抑制 |
| API 侧工具结果清理 | 关闭 | 需要内部账号环境变量显式开启；外部构建没有 |
| 缓存编辑式微压缩 | 外部构建没有 | 源码注释明确标为内部构建专用，实现文件也不在快照 |
| 历史剪裁 | 外部构建没有 | 源码注释明确标为内部构建专用，实现文件不在快照 |
| 响应式压缩 | 外部构建没有 | 源码注释明确标为内部构建专用，实现文件不在快照 |
| 上下文折叠 | 默认不生效/无法确认 | 构建期开关控制；实现文件不在快照，注释是内部实验语气 |

### 4. 默认一次压缩实际走哪条路

在外部构建、默认配置、远端没有覆盖的情况下，一次自动压缩大致是：

1. 进入主循环，取最后一次压缩边界之后的消息；
2. 工具结果聚合预算关闭，所以不执行这一层；
3. 历史剪裁不存在；
4. 微压缩被调用，但时间触发关闭、缓存编辑不可用，实际不改消息；
5. 上下文折叠不存在或未启用；
6. 估算 token 超过约 167K；
7. 会话记忆压缩因双开关默认关闭而跳过；
8. 进入整段摘要：摘要代理复用主对话前缀，生成结构化摘要；
9. 写入边界和摘要，重新注入最近文件、计划、技能、后台代理、工具/MCP 增量；
10. 继续当前回合的模型调用。

手动 `/compact` 在没有自定义指令时也会先尝试会话记忆压缩，但双开关默认关闭时同样直接跳过；之后走整段摘要，并且命令结束后不自动继续提问。

### 5. 默认阈值怎么算

默认 200K 模型、最大输出至少 20K 时：

- 有效窗口 = 200K - 20K = 180K；
- 自动压缩阈值 = 180K - 13K = 167K；
- 警告线 = 167K - 20K = 147K；
- 硬阻塞线 = 180K - 3K = 177K。

如果远端把输出上限压到 8K，摘要预留变成 8K，有效窗口变成 192K，阈值整体上移；如果模型自身最大输出低于 20K，同理。用户也可以用环境变量压低自动压缩窗口或直接覆盖阻塞线。

警告线和错误线在这版代码里使用同一个 20K 余量，所以数值重合；界面会同时进入警告与错误状态。

### 6. 默认不会压缩的情况

- 估算低于自动压缩阈值；
- 自动压缩被用户配置或环境变量关闭；
- 当前查询是压缩代理或会话记忆代理自身，避免递归；
- 上下文折叠或响应式独占模式接管了上下文管理（内部构建/特定开关）；
- 手动 `/compact` 之外的路径没有达到硬阻塞线。

普通子代理不受“压缩代理自身”这条限制；它们的上下文超限时也可以触发自动压缩。会话记忆提取则只对主 REPL 线程运行。

### 7. 默认失败行为

- 摘要代理没有产出文本：退回普通流式摘要；
- 普通流式摘要没有响应：默认不重试，报“压缩被中断”；
- 摘要请求本身提示过长：按 API 轮次从最旧分组丢弃，最多重试 3 次；
- 自动压缩失败：静默计入连续失败，连续 3 次后本会话不再尝试；
- 手动压缩失败：弹出错误通知；
- 外部构建没有响应式压缩兜底，达到硬阻塞线或压缩失败后，错误会暴露给用户。

| 条件 | 默认值/行为 |
|---|---|
| 自动压缩配置 | `true` |
| 手动压缩 | 可用，除非全局禁用 |
| 自动压缩阈值（200K 模型） | 约 167K |
| 警告线 | 约 147K |
| 硬阻塞线 | 约 177K；正常由自动压缩先处理 |
| 摘要缓存共享 | `true` |
| 摘要流式重试 | `false` |
| 单条消息工具结果聚合预算 | `false` |
| 单条工具结果转存阈值 | 约 50K 字符，始终生效（读取工具例外） |
| 时间触发微压缩 | `false`；60 分钟、保留 5 条 |
| 会话记忆提取 | `false` |
| 会话记忆压缩 | `false`，需要两个开关同时为真 |
| 会话记忆压缩保留区间 | 最少 10K token/5 条文本消息，最多 40K token |
| 响应式独占模式 | `false` |
| 输出上限压缩实验 | `false`，因此默认预留 20K 输出 |
| API 工具清理 | 关闭，且仅内部账号可开 |
| 缓存编辑/剪裁/响应式/折叠 | 外部构建默认不进入；折叠的具体外部取值无法确认 |
| 生产远端值 | 无法从本地源码确认 |

## 设计取舍

**默认把“不丢工作”放在“省 token”之前。** 自动压缩默认开启，是因为上下文溢出会让会话直接中断；整段摘要虽然贵，但比用户手动重来更可接受。聚合预算、时间微压缩、会话记忆压缩这些更激进的清理都放在开关后面，默认不改变消息内容。

**缓存共享默认开启，重试默认关闭。** 复用主对话前缀能显著降低摘要成本，所以默认尝试；流式重试会增加延迟和额外请求，因此默认关闭，只在远端明确打开时重试。

**实验路径默认关闭，外部构建不编译。** 缓存编辑、历史剪裁、响应式压缩、上下文折叠都涉及额外的服务端能力或全局状态，源码把它们放在构建期或远端开关后面；默认外部行为因此更简单、更可预测。

**单条工具结果转存是例外。** 它不改变对话语义，只是把大块内容换成可回读的引用，因此不需要实验开关；这也是默认路径里唯一稳定的“先省一点”的机制。

## 证据分级

**已证实**

- 新配置的自动压缩默认是 `true`；
- 手动 `/compact` 默认可用；
- 摘要缓存共享的代码默认是 `true`；
- 摘要流式重试的代码默认是 `false`；
- 单条消息工具结果聚合预算默认关闭；
- 时间触发微压缩默认关闭，默认 60 分钟、保留 5 条；
- 会话记忆提取与会话记忆压缩的开关默认都是 `false`；
- 会话记忆压缩的默认保留区间是 10K/5 条/40K；
- 响应式独占模式默认关闭；
- 输出上限压缩实验默认关闭，因此默认摘要预留 20K；
- API 工具清理需要内部账号环境变量；
- 源码注释明确把缓存编辑、历史剪裁、响应式压缩标为内部构建专用；
- 单条工具结果的约 50K 字符转存阈值是默认生效的。

**合理推断**

- 外部发行版不会包含缓存编辑、历史剪裁、响应式压缩这几条路径；
- 上下文折叠从注释和缺失实现看更像内部实验，外部默认大概率不启用，但源码没有明确写出；
- 默认外部行为是“自动整段摘要 + 压缩后重建”，而不是完整的多层流水线；
- 默认不开启聚合预算，意味着多个中等大小工具结果可以在同一条消息里累计到很大，直到自动压缩处理。

**无法确认**

- 生产 GrowthBook 对各开关的真实下发值；
- 外部发行包对 `CONTEXT_COLLAPSE` 的构建期取值；
- 缓存编辑式微压缩的具体触发阈值与保留条数；
- 服务端缓存编辑、上下文管理的实际执行语义；
- 不同模型、不同账号类型下的实际默认行为差异。
