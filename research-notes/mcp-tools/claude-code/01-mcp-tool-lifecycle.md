# MCP 工具接入 - Claude Code - 01 - 作为 MCP 客户端的工具发现、暴露与调用

---

我想探究一下 Claude Code / Codex 作为 MCP 客户端，如何发现外部 MCP Server 提供的工具，把工具暴露给模型，并在模型请求调用后完成权限判断、协议调用、结果转换与失败处理。

---

本文只讨论 Claude Code 作为 MCP 客户端的工具链路，不讨论 MCP resources、prompts，也不讨论 Claude Code 自己作为 MCP Server 对外提供工具的实现。

## 结论摘要

Claude Code 把 MCP 工具适配成与内置工具相同形状的动态工具，然后并入同一个工具池。初始连接成功后，它向每个声明了工具能力的 Server 请求一次工具清单，把 Server 名和工具名编码进模型可见名称，并保留原始名称用于真正调用。模型看到的是一套统一工具，因此后续的参数解释、审批、并发编排、错误回传都可以复用内置工具机制。

默认情况下，MCP 工具不会一开始就把完整 schema 塞进模型上下文。只要当前模型和运行环境支持工具搜索，MCP 工具就进入延迟加载目录；模型先看到工具名或搜索入口，需要时再取完整定义。`anthropic/alwaysLoad` 可以让特定工具跳过这条路径。

调用时，Claude Code 先执行通用权限闸门。动态 MCP 工具自身只返回“需要权限”的透传结果，所以默认会触发用户审批；已有允许规则、绕过权限模式或 hooks 才可能直接放行。审批通过后，客户端通过 MCP `tools/call` 发请求，处理 OAuth 重连、会话过期、长任务、进度、结果归一化和大结果降级。

## 机制展开

```mermaid

  A[多来源 MCP 配置] --> B[并行连接与初始化]
  B --> C[工具清单请求]
  C --> D[适配为统一工具]
  D --> E[权限规则过滤与合并]
  E --> F{工具搜索可用?}
  F -->|是| G[只暴露名称与搜索入口]
  F -->|否| H[直接暴露完整 schema]
  G --> I[模型选择工具]
  H --> I
  I --> J[通用工具编排与审批]
  J --> K[MCP 协议调用]
  K --> L[结果归一化与容量控制]
  L --> M[工具结果回到模型]
```

### 1. 先发现 Server，再建立连接

Claude Code 会合并企业、用户、项目、本地、插件和 claude.ai connector 等来源。项目配置沿父目录向当前目录合并，越接近当前目录的项目配置优先级越高；企业配置存在时可以独占 MCP 配置；插件 Server 与手工 Server 指向同一命令或 URL 时，手工配置优先。这个层次先解决“要不要连接哪个 Server”，而不是工具协议本身。

禁用的 Server 不建立连接。对曾返回未授权的远程 Server，客户端有短时未授权缓存，避免反复探测。实际建立连接时，本地进程型 Server 与远程 Server 分组并行：默认本地最多 3 个同时连接，远程最多 20 个；这些值都可以由环境变量调整。

客户端支持本地 stdio、远程 SSE、Streamable HTTP、WebSocket、claude.ai 代理以及 SDK 进程内 Server。连接阶段通过 MCP 初始化握手取得 Server 能力、版本和说明。默认连接超时约 30 秒；HTTP 普通请求另有约 60 秒的请求级超时，而长连接事件流不套用这 60 秒限制。

连接结果按 Server 隔离：一个 Server 超时、启动失败或需要认证，不会阻止其他 Server 的工具进入工具池。认证失败会生成一个专用的“认证”伪工具，模型可以请求用户启动 OAuth；认证完成后，伪工具会被真实工具替换。

### 2. 只在能力允许时请求工具清单

连接成功后，客户端检查 Server 是否声明工具能力。若没有声明，直接返回空列表，不发送 `tools/list`。若声明了，就请求工具清单、清洗其中的 Unicode 数据，并把结果缓存在按 Server 名索引的有界缓存中。

当前快照每次只发送一个不带 cursor 的 `tools/list` 请求，没有看到继续读取 `nextCursor` 的逻辑。[已证实] 因此，工具数量超过 Server 第一页返回上限时，Claude Code 在本地不会自行翻完所有页。这是一个明确的协议边界，而不是工具本身只有这些能力。

工具清单失败会被记录并转换为空工具列表。对当前会话而言，这个 Server 看起来存在但没有可用工具，其他 Server 继续工作。

如果 Server 声明工具清单可变化，Claude Code 会监听 `tools/list_changed`。收到通知后，它使该 Server 的工具缓存失效，重新请求清单，再替换应用状态中属于该 Server 的那一组工具。这个路径不需要用户手动重连。

### 3. 把 MCP 工具改造成统一工具

每个远端工具会复制一份通用 MCP 工具定义，并覆盖名称、说明、schema、安全提示、执行函数等字段。模型可见名称默认是：

```text
mcp__<规范化后的 Server 名>__<规范化后的工具名>
```

Server 名和工具名中的非法字符会变成下划线。原始 Server 名和工具名仍单独保存在工具元数据中，真正向 Server 调用时使用原始工具名。特殊 SDK 模式可以通过环境变量跳过前缀，此时允许 MCP 工具覆盖同名内置工具；普通外部 Server 不走这条路径。

工具说明最多保留 2,048 个字符。输入定义直接采用 Server 返回的 JSON Schema，并把它作为模型请求中的工具参数 schema；但执行前使用的本地通用输入 schema 是“任意对象”，不会按远端 JSON Schema 再严格校验一遍。远端 Server 仍是参数语义的最终责任方。

Server 提供的注解会影响本地策略：

- `readOnlyHint` 同时决定工具是否声明为只读、是否允许并发。
- `destructiveHint` 和 `openWorldHint` 成为工具风险属性。
- `_meta` 中的 `anthropic/alwaysLoad` 可以阻止工具被延迟加载。
- `_meta` 中的 `anthropic/searchHint` 成为工具搜索的辅助文本。

对 IDE Server 还有额外白名单，只放入两个允许的 IDE 工具，避免把 IDE 的内部工具全部暴露给主模型。

### 4. 合并工具池并决定模型的初始可见面

所有 MCP 工具先经过拒绝规则过滤。规则可以精确到 `mcp__server__tool`，也可以写成 `mcp__server` 或 `mcp__server__*` 来屏蔽整个 Server。被整工具拒绝的工具不会进入模型可见工具池。

之后，内置工具与 MCP 工具按名称排序并去重。内置工具保持连续前缀，MCP 工具随后排列，以稳定提示缓存顺序。名称冲突时内置工具优先。

当模型支持工具搜索时，MCP 工具默认被标记为延迟工具。初始请求只保留非延迟工具、工具搜索入口，以及已经在前文被发现过的延迟工具；尚未被发现的 MCP 工具不会把完整参数 schema 放进初始请求。模型搜索后，工具引用会把完整 schema 带回后续请求。

工具搜索模式默认为开启，但也受模型是否支持工具引用、API provider、显式环境开关和远端实验配置影响。关闭工具搜索后，MCP 工具定义直接完整暴露。这个差异只改变上下文如何加载工具，不改变工具调用协议。

### 5. 模型调用先进入统一工具编排

模型返回工具调用后，执行器先从当前工具池中按模型可见名称找到对应工具。找不到时直接生成一个错误工具结果让模型继续，而不是让查询循环崩溃。

如果同一批调用都是并发安全工具，Claude Code 会并行执行；遇到非并发安全工具则切换为串行。动态 MCP 工具的并发安全判断来自 Server 的 `readOnlyHint`，默认并发上限为 10，可由环境变量调整。没有只读提示的工具默认按串行处理。

工具执行前会经过 hooks、输入解释、权限判断和审批。这个阶段与内置工具共用同一条执行管线，没有另造一套只服务 MCP 的权限协议。

### 6. 权限判断顺序

对 MCP 工具，关键的权限顺序是：

1. 整个工具命中拒绝规则：拒绝。
2. 整个工具命中必问规则：询问用户。
3. 调用工具自身的权限检查。
4. 若处于绕过权限模式：允许。
5. 若命中整个工具的允许规则：允许。
6. 其余“透传”结果转换为询问。

动态 MCP 工具自己的权限检查始终返回透传，并建议“允许这个完整工具名”。因此，MCP 工具**默认会请求用户确认**；Server 的 `readOnlyHint` 本身不会自动授予调用权限。它主要影响并发和风险展示。允许规则、全局绕过模式或 hooks 才可能让调用直接通过。

如果权限系统要求询问，交互模式会展示审批界面，用户可以选择单次允许或写入本地设置；无头或 SDK 模式则通过各自的审批回调完成。拒绝会在调用 MCP Server 之前结束，并把错误工具结果返回给模型。

### 7. 协议调用与动态恢复

审批通过后，工具会再次确认当前连接可用，再向 MCP Server 发送 `tools/call`。请求携带原始工具名、模型给出的参数，以及可选的工具调用标识元数据。长任务会向模型侧发送开始、进度、完成和失败事件；客户端还会周期记录“仍在运行”的调试信息。

默认工具调用超时约为 27.8 小时，可通过环境变量调整。代码没有单纯依赖 MCP SDK 的内部超时，而是额外用竞速方式加了一层超时，避免某些流式连接断开后请求永久悬挂。

以下恢复逻辑发生在协议层：

- 远程会话过期或连接关闭时，清理连接和工具缓存，再以新会话重试一次。
- 401 或明确的未授权错误转为 `needs-auth` 状态，并把可理解的错误返回给模型。
- Server 返回“需要 URL elicitation”时，先运行 elicitation hooks；没有 hooks 处理则交给用户或 SDK 回调，最多重试 3 次。
- SSE 或 HTTP 连接反复出现终止性错误时，关闭旧 transport，使下次调用重新连接，并拒绝旧连接的待处理请求，避免永久等待。

### 8. 结果转换成模型可消费的内容

MCP 结果并不原样塞回模型，而是按内容类型转换：

- 文本转成文本块。
- 图片先按模型限制缩放和压缩，再转成图片块。
- 音频与其他二进制资源写入本地文件，模型只收到带路径和 MIME 信息的文本说明。
- 文本资源内联为文本，图片资源作为图片处理，资源链接转成文本。
- 有 `structuredContent` 时，优先序列化为 JSON 文本。
- 原始的 `_meta` 和结构化内容会作为工具结果的旁路元数据保留。

大结果会检查大小。若并非图片，通常写入磁盘，再给模型一个包含文件路径、大小和读取建议的短结果；若包含图片、功能被显式关闭或写盘失败，则退回截断路径。这样既避免一次性耗尽上下文，也尽量保留继续处理大结果的能力。

### 9. 失败如何回到模型

协议调用抛错或 Server 明确返回 `isError` 时，MCP 适配层把它转成工具异常。通用工具执行器捕获后返回一个 `is_error` 工具结果，让模型知道失败原因并有机会换参数、换工具或向用户解释。

Server 返回错误结果且包含多个内容块时，本地错误摘要只读取第一个文本块；完整旁路元数据仍可能保留。这意味着错误结果的结构化字段未必都会出现在错误文本中，模型可能需要依赖服务端把可行动信息放在首块。

用户取消会让调用信号中止。连接层、权限等待和工具查询都能看到取消；正在等待审批时取消会直接结束，不会继续向 Server 发请求。

## 条件与边界

- **已证实**：MCP 工具被适配为统一工具；内置工具优先去重；Server 级拒绝规则可在模型看到工具之前生效。
- **已证实**：MCP 工具自身默认要求审批，只通过通用权限规则、模式或 hooks 放行。
- **已证实**：连接失败、工具清单失败和调用失败都在 Server 或工具结果边界内降级，不直接让整个模型循环崩溃。
- **已证实**：当前工具发现只发一次 `tools/list`，没有消费分页 cursor。
- **已证实**：工具搜索默认期望延迟加载 MCP 工具，但最终是否启用取决于模型、provider、环境开关和远端配置。
- **合理推断**：统一适配降低了主循环复杂度，并把 MCP 特例限制在发现、连接、协议调用和结果转换层。
- **无法确认**：GrowthBook 远端开关和构建期 feature 在正式发行版中的真实取值；只能确认相应分支存在。
- **无法确认**：实际第三方 Server 是否返回分页清单、是否提供准确注解，以及它们是否把最有用的错误信息放在首个内容块。

## 设计取舍

Claude Code 的核心选择是“让 MCP 工具看起来像内置工具”。这换来统一审批、统一编排、统一错误格式和更小的主循环改动，但也意味着远端 JSON Schema 与本地通用输入 schema 之间存在一层不完全对称：前者塑造模型输出，后者只保证收到一个对象。

默认询问比信任 Server 的 `readOnlyHint` 更保守。代价是只读 MCP 工具也需要用户先授权；收益是恶意或错误标注的 Server 不能仅凭注解获得执行权。

延迟工具搜索把工具定义从“每轮常驻上下文”改为“需要时加载”，适合工具很多的场景；代价是多一次模型与 harness 的搜索往返，并依赖模型支持工具引用。

单页工具发现实现简单，也避免了游标异常和超大目录处理，但会漏掉 Server 分页后的工具。Codex 在这点上做了明确的页数和总条目上限，并完整消费 cursor，这是两者最显著的目录规模边界差异。

## 证据分级

### 已证实

- 配置来源、连接方式、并行批次、连接超时和失败隔离。
- 工具发现只请求一次，并在清单变化通知后刷新。
- 名称编码、说明截断、注解到并发和风险属性的映射。
- 工具池去重、拒绝规则过滤、工具搜索延迟加载。
- 默认 MCP 审批行为、允许规则的 Server 级匹配、绕过模式。
- 会话过期重试、OAuth 认证降级、URL elicitation 重试、调用超时。
- 文本、图片、音频、资源、结构化结果和大结果的处理路径。

### 合理推断

- “统一工具协议”是为了复用现有权限、hooks、并发和错误处理，而不是为 MCP 单独建立执行系统。
- 默认询问的设计动机是避免信任外部 Server 自报的只读状态。
- 大结果写盘是为了让模型在有限上下文中保留继续检索大结果的能力。

### 无法确认

- 正式发行环境中的远端开关和 feature 默认值。
- 具体外部 Server 的分页、注解准确性、错误内容布局和工具数量。
- SDK 与第三方传输实现是否会在用户取消时向 Server 发出额外的协议级取消通知。
